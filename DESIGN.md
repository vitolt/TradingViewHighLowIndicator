# План разработки индикатора High-Low Levels для TradingView

## Context
Разрабатывается индикатор для TradingView, который отображает горизонтальные линии уровней (максимумы и минимумы дней, недель, месяцев). Индикатор должен быть универсальным для любых тайм-фреймов и инструментов, интуитивно настраиваться, и корректно отображать логику "мёртвых" уровней (заканчивающихся при пересечении).

### Ключевые требования
1. **Логика уровней**: Линия заканчивается в точке пересечения ценой и становится "блёклой"
2. **Периоды**: Только завершённые свечи, глубина по умолчанию 10 периодов, настраивается
3. **Тайм-фреймы**: Одна логика для всех, но дневные/недельные/месячные уровни определяются автоматически
4. **Объединение уровней**: Если экстремумы разных периодов совпадают по цене — один уровень с комбинированным лейблом
5. **Визуализация**: Настраиваемые цвет, ширина, стиль для каждого типа (Daily High/Low, Weekly, Monthly)
6. **Часовой пояс**: Настраивается пользователем для определения границ периодов

## Архитектурный подход

### Язык и структура
- **Язык**: Pine Script (v5) — стандарт для индикаторов TradingView
- **Структура**:
  - `input()` для всех настроек
  - Модульные функции для расчёта периодов и экстремумов
  - Вспомогательные функции для логики пересечения
  - Цикл вывода линий с динамическим завершением

### Основные компоненты

#### 1. **Входные параметры (Settings)**
```
- lookback_depth: int (1-500, default 10)
- daily_high: bool, color, width, style, label
- daily_low: bool, color, width, style, label
- weekly_high: bool, color, width, style, label
- weekly_low: bool, color, width, style, label
- monthly_high: bool, color, width, style, label
- monthly_low: bool, color, width, style, label
- transparency: int (0-100, default 20)
- extend_lines: bool (default true)
```

**Примечание**: Часовой пояс берётся автоматически с графика TradingView.

#### 2. **Функция определения периодов и получение данных старших ТФ**
```pine
- get_day_boundary(time) → day_start_time
- get_week_boundary(time) → week_start_time
- get_month_boundary(time) → month_start_time
- fetch_daily_high() → request.security("SYMBOL", "D", high)
- fetch_weekly_high() → request.security("SYMBOL", "W", high)
- fetch_monthly_high() → request.security("SYMBOL", "M", high)
- cache_update_check() → перепроверка кэша при переходе на новый период
```
**Логика**: Использует `request.security()` для получения экстремумов старших ТФ. Значения кэшируются и обновляются только при смене периода. На текущем графике ищутся только уровни того же периода или старше.

#### 3. **Функция поиска экстремумов**
```pine
- find_extrema_in_lookback(depth) → [price_values]
```
**Логика**: На текущем графике собирает экстремумы за глубину просмотра. Объединяет экстремумы старших ТФ (полученные через request.security).

#### 4. **Функция проверки пересечения**
```pine
- is_level_crossed(level_price, current_bar_idx, level_created_at) → bool
```
**Логика**: Проверяет, была ли цена выше/ниже уровня после его создания, используя high/low свеч.

#### 5. **Функция вывода линий**
```pine
- draw_level(price, label_text, color, width, style, is_crossed, transparency)
```
**Логика**: Создаёт line объект, устанавливает его параметры, регулирует прозрачность в зависимости от статуса пересечения.

## Ключевые технические решения

### Проблема: Ограничения Pine Script
- **Лимит объектов**: TradingView ограничивает количество линий/лейблов (~300 объектов в бесплатной версии)
  - **Решение**: Удалять старые линии при достижении лимита, фокусироваться на видимой области

### Проблема: Расчёт периодов на разных часовых поясах
- **Сложность**: Pine Script работает с UTC, нужно преобразовывать в нужный пояс
  - **Решение**: Использовать формулу: `local_time = time + (tz_offset * 60 * 60 * 1000)`, затем извлекать day/month/year

### Проблема: Совпадающие уровни разных периодов
- **Сложность**: Нужно отследить, какие периоды дали одинаковый максимум
  - **Решение**: Хранить struct/массив с информацией о каждом уровне (цена, тип периодов, статус пересечения)

### Проблема: Пересечение уровня
- **Сложность**: Нужно найти точный бар, где произошло пересечение
  - **Решение**: Проверить, находится ли high/low текущего бара выше/ниже уровня; если да — вычислить точное положение на баре
