- ✅ Типы данных: `bool`, `int`, `float`, `string`, `color`, `line`, `label`, `box`, `polyline`
- ✅ User Defined Types (UDT) и работа с ними

- ✅ `line.new()`, `line.set_x2()`, `line.delete()` — работа с линиями
- ✅ `label.new()`, `label.set_text()`, `label.set_x()` — работа с лейблами
- ✅ `input()`, `input.int()`, `input.color()`, `input.string()` — параметры индикатора

### Архитектура индикаторов
- ✅ Структура индикатора: настройки → типы → функции → логика → вывод

## 📌 Знаю и избегаю

### ❌ Частые ошибки в Pine v5:
1. Использование `na(line)` или `na(label)` как аргумента функции → ✅ Использую `var`
2. Инициализация line/label типов в конструкторе UDT → ✅ Создаю без инициализации, присваиваю позже
3. Забывание `array.set()` после изменения UDT в массиве → ✅ Всегда вызываю `array.set()` после изменения
4. Использование `timeframe.in_minutes()` (нет такой функции) → ✅ Использую `timeframe.period`
5. Забывание `!= 0` при проверке `ta.change()` → ✅ Пишу `if ta.change(time("D")) != 0`

### ❌ Функции/методы которых нет в Pine v5:
- `timeframe.in_minutes()` → Используется `timeframe.period`
- `string.contains()` → Используется `str.contains()`
- `bar.index` → Используется `bar_index`
- `chart.symbol` → Используется `syminfo.tickerid`
- `line()` как конструктор → Используется `line.new()`
- `label()` как конструктор → Используется `label.new()`

## 🎯 Стиль кода

### Структура файла
```pine
//@version=5
indicator("Name", overlay=true, max_lines_count=500, max_labels_count=500)

// ============================================================================
// SETTINGS
// ============================================================================
[input() параметры]

// ============================================================================
// TYPE DEFINITIONS
// ============================================================================
[type definitions с var для line/label]

// ============================================================================
// HELPER FUNCTIONS
// ============================================================================
[вспомогательные функции]

// ============================================================================
// GLOBAL STATE
// ============================================================================
[var переменные]

// ============================================================================
// MAIN LOGIC
// ============================================================================
[основная логика]
```

### Именование
- `snake_case` для переменных и функций: `dh_val`, `f_get_style()`, `display_color_val`
- `camelCase` для параметров input: `dh_enabled`, `dh_color`, `dh_width`
- Префиксы для функций: `f_` для обычных функций, `ta.` для встроенных TA функций
- Префиксы для переменных: `var` для глобальных, `lv` для Level объектов

### Комментарии
```pine
// Разделители для секций
// ============================================================================

// Inline комментарии для сложной логики
if ta.change(time("D")) != 0  // Проверка смены дня
```

## 📚 Процесс разработки

### При разработке нового индикатора:
1. **Читаю требования** (`REQUIREMENTS.md`)
2. **Проектирую архитектуру** (`DESIGN.md`, `SDD.md`)
3. **Пишу код** с учётом ограничений Pine v5
4. **Проверяю синтаксис** перед компиляцией
5. **Документирую** (`INSTRUCTION.md`, `VERIFICATION.md`)
6. **Логирую ошибки** в `ERRORS_LOG.md` с решениями

### При исправлении ошибок:
1. Читаю сообщение об ошибке полностью
2. Проверяю синтаксис и версию функции
3. Документирую в `ERRORS_LOG.md` для будущих разработок
4. Исправляю все похожие места в коде
5. Проверяю, что нет новых ошибок
