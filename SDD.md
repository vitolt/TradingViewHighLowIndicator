# Software Design Document (SDD)
## Индикатор High-Low Levels для TradingView

**Версия**: 1.0  
**Дата**: 2026-10-07  
**Статус**: Design Phase

---

## 1. Обзор

### 1.1 Назначение
Индикатор High-Low Levels отображает на графиках TradingView горизонтальные уровни, обозначающие максимумы и минимумы дневных, недельных и месячных периодов. Индикатор динамически управляет линиями: линии заканчиваются при пересечении ценой и отображаются с меньшей яркостью.

### 1.2 Целевая аудитория
- Трейдеры, работающие с техническим анализом
- Пользователи TradingView всех уровней
- Применимо для любых инструментов (акции, крипто, фьючерсы, валюты)

### 1.3 Основные преимущества
- Универсальность (работает на любых тайм-фреймах одинаково)
- Простая настройка (гибкие параметры цвета, ширины, стиля для каждого типа)
- Интуитивная логика (уровни "мертвеют" при пересечении)
- Поддержка временных зон (для разных торговых сессий)

## 2. Требования к функциональности

### 2.1 Основная функциональность (Must Have)
| Функция | Описание |
|---------|---------|
| **Отображение уровней** | Рисовать 6 типов горизонтальных линий: DH, DL, WH, WL, MH, ML |
| **Логика пересечения** | Завершать линию в точке пересечения (по high/low свечи) |
| **Блёдность** | Снижать прозрачность пересечённых уровней |
| **Завершённые периоды** | Использовать только закрытые свечи (не включать текущую) |
| **Глубина просмотра** | Настраиваемая (1-500), по умолчанию 10 |
| **Часовой пояс** | Выбор часового пояса для определения границ периодов |
| **Объединение уровней** | Одна линия для совпадающих максимумов/минимумов с комбинированным лейблом |

### 2.2 Дополнительная функциональность (Nice to Have)
| Функция | Описание |
|---------|---------|
| **Экспорт данных** | Вывод информации о уровнях в таблице |
| **Алерты** | Уведомления при пересечении уровня |
| **Дневник уровней** | История всех созданных и пересечённых уровней |

## 3. Спецификация входных параметров

### 3.1 Основные настройки
```pine
input(int)    lookback_depth = 10              // Глубина просмотра назад
```

**Часовой пояс**: отдельного параметра нет. Границы дня/недели/месяца определяются
часовым поясом, выбранным на графике TradingView (`syminfo.timezone` / встроенная
агрегация `request.security`).

### 3.2 Настройки Daily High
```pine
input(bool)   daily_high_enabled = true        // Включить/выключить
input(color)  daily_high_color = color.green   // Цвет линии
input(int)    daily_high_width = 1             // Ширина (1-5)
input(string) daily_high_style = "solid"       // Стиль (solid, dashed, dotted)
input(string) daily_high_label = "DH"          // Текст лейбла
```

### 3.3 Аналогичные для: Daily Low, Weekly High, Weekly Low, Monthly High, Monthly Low

### 3.4 Глобальные параметры
```pine
input(int)    transparency = 20                // Прозрачность блёдных линий (0-100)
input(bool)   extend_lines = true              // Расширять линии за границы видимой области
```

### 4.2 Ключевые функции

#### Модуль 1: Расчёт периодов и данных старших ТФ
```pine
f_get_day_boundary(timestamp)               → timestamp
f_get_week_boundary(timestamp)              → timestamp
f_get_month_boundary(timestamp)             → timestamp
f_is_timeframe_qualified(current_tf, level_tf) → bool
f_fetch_higher_tf_data(level_type)          → [high, low, timestamp]
```

**request.security использование**: Для получения максимума/минимума дневного/недельного/месячного ТФ на текущем графике используется `request.security("SYMBOL", "D|W|M", high|low)`. Значения кэшируются в переменных и обновляются при смене периода.

#### Модуль 2: Поиск экстремумов
```pine
f_find_high_in_lookback(depth)              → float
f_find_low_in_lookback(depth)               → float
f_unique_prices(prices_array)               → array<float>
f_cache_higher_tf_extrema()                 → void
```

**Кэширование**: Экстремумы старших ТФ хранятся в переменных и пересчитываются только при переходе на новый период соответствующего ТФ (проверка через `ta.change(dayofmonth)`, `ta.change(weekofyear)` и т.д.).

#### Модуль 3: Проверка пересечения
```pine
f_is_level_crossed(level_price, from_bar, to_bar) → bool
f_get_cross_bar_index(level_price, from_bar)      → int
```

#### Модуль 4: Отрисовка
```pine
f_draw_level_line(price, bar_idx, label_text, settings) → void
f_set_line_alpha(line_obj, alpha_percent)               → void
f_create_line_label(price, text, color)                 → void
```

## 5. Структуры данных

### 5.1 Level Info Structure (Struct)
```pine
type LevelInfo
    float   price          // Цена уровня
    string  types          // Комбинированный тип (e.g., "DH+WH+MH")
    int     created_bar    // Индекс бара создания
    int     crossed_bar    // Индекс бара пересечения (-1 если не пересечен)
    line    line_obj       // Объект линии TradingView
    label   label_obj      // Объект лейбла
    bool    is_high        // true для high, false для low
```

### 5.2 Period Info
```pine
type PeriodInfo
    int     start_bar      // Первый бар периода
    int     end_bar        // Последний бар периода
    float   high           // Максимум периода
    float   low            // Минимум периода
    string  period_type    // "daily", "weekly", "monthly"
```

## 6. Алгоритм главного цикла

```
// Инициализация и кэширование старших ТФ (выполняется один раз)
daily_high_cached = request.security(syminfo.tickerid, "D", high)
daily_low_cached = request.security(syminfo.tickerid, "D", low)
weekly_high_cached = request.security(syminfo.tickerid, "W", high)
weekly_low_cached = request.security(syminfo.tickerid, "W", low)
monthly_high_cached = request.security(syminfo.tickerid, "M", high)
monthly_low_cached = request.security(syminfo.tickerid, "M", low)

// Главный цикл обработки баров
FOR each bar (от текущего до lookback_depth назад):
  1. Проверить фильтр: текущий ТФ >= требуемый ТФ уровня
     (например, если ТФ = "1W", показывать только WH, WL, MH, ML)
  
  2. Для дневных уровней (если квалифицированы):
     - Если bar на дневном графике совпадает с дневным периодом
     - Найти high/low за этот день на текущем графике
     - Проверить, совпадает ли с cached daily_high/low
  
  3. Для недельных и месячных уровней:
     - Использовать cached значения (полученные через request.security)
     - Кэш обновляется автоматически, когда наступает новый период
  
  4. Объединить уровни, которые совпадают по цене
     (например, если DH = WH, создать один лейбл "DH+WH")
  
  5. Для каждого уникального уровня:
     - Проверить, был ли он пересечен (price > high или price < low)
     - Найти точный бар пересечения
  
  6. Отрисовать линию:
     - Если пересечена: линия от начала до бара пересечения, низкая прозрачность
     - Если не пересечена: линия до текущего бара или конца видимой области
  
  7. Отобразить лейбл с типом уровня и ценой
END FOR
```

## 7. Технические ограничения Pine Script

| Ограничение | Значение | Решение |
|-------------|----------|---------|
| Макс. линий | ~300 (free), ~500 (pro) | Удалять старые линии вне видимой области |
| Макс. лейблов | Аналогично линиям | Группировать лейблы, показывать только видимые |
| Макс. баров в истории | 5000 | Ограничить lookback_depth |
| Точность расчётов | 32-бит float | Использовать округление до 2 знаков |

## 8. Критерии тестирования

### Unit Tests (логика)
- [ ] Правильное кэширование и обновление экстремумов старших ТФ
- [ ] Корректный фильтр по текущему ТФ (не показывать младшие ТФ)
- [ ] Правильная логика объединения уровней с одинаковой ценой

### Integration Tests
- [ ] Отображение на 1m графике: DH, DL, WH, WL, MH, ML
- [ ] Отображение на 1W графике: WH, WL, MH, ML (без DH, DL)
- [ ] Отображение на 1M графике: только MH, ML
- [ ] Проверка пересечения на исторических данных
- [ ] Корректная отрисовка линий от первой доступной даты при нехватке истории

### UI/UX Tests
- [ ] Лейблы не перекрывают цены
- [ ] Цвета ясны на светлой и тёмной темах
- [ ] Ширина линий удобна для чтения
- [ ] "Блёклые" линии чётко отличаются от активных

## 10. Риски и миtigations

| Риск | Вероятность | Влияние | Mitigation |
|------|-------------|--------|-----------|
| Ограничение объектов TradingView | Высокая | Среднее | Динамическое удаление старых линий |
| Неточные расчёты периодов | Средняя | Высокое | Тестирование на разных поясах, документация |
| Производительность на больших lookback | Средняя | Среднее | Оптимизация алгоритма, рекомендация ≤ 50 |

## 11. Заключение

Данный SDD определяет архитектуру и подход к разработке индикатора High-Low Levels. Реализация следует указанным модулям и структурам данных для обеспечения надёжности и масштабируемости.
